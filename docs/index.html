shieldcn-zig

A pure-Zig badge engine with SVG, PNG, and JSON output. No external rendering dependencies. SLSA Level 3 CI/CD.

Output Formats

SVG (direct XML emission), PNG (pure-Zig rasterizer, no libpng), and JSON. All three from the same URL — just change the extension.

SVG
/badge/build-passing-green.svg
PNG (pure-Zig rasterizer)
PNG — green
/badge/build-passing-green.png
PNG — red
/badge/build-failing-red.png
PNG — blue
/badge/coverage-92%25-blue.png
JSON
/badge/build-passing-green.json
{"label":"build","message":"passing","color":"#97ca00","labelColor":"#27272a"}
08

Badge Groups

Stack N static badges vertically into one SVG via /group/spec|spec|....svg. Each sub-spec follows the static badge form label-message-color.

2 badges
/group/build-passing-green|coverage-92%25-blue.svg
3 badges
/group/build-passing-green|coverage-92%25-blue|license-MIT-orange.svg

Audit Logging

Every HTTP request emits one audit line to stderr. Runtime path uses std.log.info with a compact space-delimited format. Full JSON available via formatRecord().

Runtime stderr output
info: 737716767222000 GET /badge/build-passing-green.svg 200 1516
info: 737717089776000 GET /badge/build-passing-green.png 200 2823
info: 737717408621000 GET /group/build-passing-green|coverage-92%25-blue.svg 200 1734
info: 737718048495000 GET /health 200 17
info: 737718371596000 POST /health 405 14
Full JSON (via formatRecord)
{"ts_ns":1753674280123456789,"method":"GET","path":"/badge/build-passing-green.svg","provider":"badge","format":"svg","status":200,"latency_us":42,"cache_hit":false}
